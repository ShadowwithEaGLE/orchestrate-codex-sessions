## 工作单元判断示例

| 场景 | 选择 | 原因 |
|---|---|---|
| 已知文件中的小修复 | Level 0 | 主任务必须完整阅读准确代码，交接没有收益 |
| 大仓库中定位三个独立调用链 | Level 1 | 可并行侦察，结果能压缩为 `file:line` |
| 紧凑静态原型，外加现状和验收调研 | Level 1 | subagent 侦察，主任务保持唯一实现责任 |
| 两个互不重叠的小补丁能在本轮完成 | Level 1 | 轨迹可丢弃，主任务整合、测试并保持最终所有权 |
| 任务需要用户稍后直接进入并继续纠偏 | Level 2 | 需要持久身份、历史和用户可寻址性 |
| Core、UI、打包、QA 有明确依赖 | Level 2 串行 | 需要持久所有权和阶段闸门 |
| 两个模块可独立写入不同 worktree | Level 2 并行 | 交付责任独立且文件系统隔离 |
| 两个任务共享 checkout 并修改同一文件 | 串行 | 可见任务不提供文件隔离 |

如果不能明确指出拆分减少了什么风险、上下文或时间，就不要拆。Level 1 还必须证明完整轨迹可以安全丢弃；Level 2 必须证明持久身份或状态有独立价值。

## 阶段闸门

### Core → UI

- 数据模型和公开接口已存在。
- UI 所需 product、target、类型和构建入口可用。
- 正常、边界和损坏输入有真实检查。
- Core 只修改自己的所有权范围。
- 已记录无法运行的检查和原始环境错误。

### UI → Package/QA

- UI 只使用已验收接口。
- 用户要求的每个可见类别、状态和细节都有 Acceptance 项。
- 构建通过；可访问性基础和错误状态已检查。
- 没有用截断、占位或总量指标代替用户要求的明细。

### Package/QA → Final

- Release 和打包产物来自已验收源码。
- 真实数据与程序输出交叉核对。
- 用户可见入口、当前运行状态和操作方式明确。
- QA 保持只读；缺陷均经 Repair 和原 QA 复验。
- 未验证项没有被写成通过。

## 证据矩阵

| 维度 | 最低证据 | 不能替代它的内容 |
|---|---|---|
| Level 1 路由 | 全部 Level 1 条件成立、结果已回传并由主任务验收 | “任务比较小” |
| Level 2 可见性 | 任务列表中的真实 thread ID、标题、项目、环境和状态 | 创建调用返回成功或内部 agent ID |
| 范围 | 实际修改文件与所有权对照 | 任务自述“只改了这些” |
| 逻辑 | fixture、自检或回归检查输出 | 仅代码审阅 |
| 构建 | 实际 Debug/Release 命令和退出结果 | 语法看起来正确 |
| 打包 | 产物路径、生成命令和来源一致性 | Release build 单独成功 |
| 真实数据 | 与权威来源的独立交叉核对 | Mock 或样例数据 |
| 可见 UI | 截图、浏览器/应用可见检查或明确人工验收 | 进程存在 |
| 运行状态 | 启动、刷新、退出、进程或端口证据 | 文件已生成 |
| 安全边界 | 网络、权限、敏感内容、daemon、发布状态 | 没观察到错误 |
| 未验证项 | 原始阻塞、影响范围、仍可确认内容 | 模糊的“环境问题” |

## 缺陷与环境阻塞

使用三个互斥结果：

- `PASS`：该 Acceptance 有直接证据。
- `DEFECT`：产品行为不符合期望，能给出复现和影响。
- `ENV BLOCK`：环境阻止验证；不能据此推断产品通过或失败。

DEFECT 报告至少包含：

1. 紧凑的 `file:line` 或用户可见位置；
2. 复现场景；
3. 实际行为与期望行为；
4. 影响；
5. 建议的最小所有权范围，不直接越权修复。

环境阻塞至少包含：

1. 原始错误；
2. 尝试过的安全检查；
3. 被阻止的 Acceptance；
4. 仍然成立的证据边界。

## 常见失败模式

- **把需求收窄**：截图要求分类明细，却只交付总量。把每个可见元素写成独立 Acceptance。
- **总管越权编码**：主任务与已派发实现任务同时修改同一范围。保持唯一所有权。
- **内部代理冒充可见任务**：把 `spawn_agent` 返回的内部 agent ID 当成 thread ID。Level 2 必须通过任务列表验收。
- **过度升级**：可在本轮压缩交付的小任务也创建侧边栏 Session。全部 Level 1 条件成立时保留内部 subagent。
- **隐式触发扩大授权**：Skill 自动匹配后直接创建可见任务。先取得一次 Level 2 创建确认。
- **subagent 变成长支线**：需要多轮用户决策仍留在内部侦察。升级为可见任务。
- **可见任务被误认为隔离**：共享 checkout 并发写入。改为串行或独立 worktree。
- **QA 顺手修复**：发现、修复和复验混在一起。用最小 Repair，再回原 QA。
- **任务自报完成即放行**：缺少实际范围和命令证据。主任务必须复核闸门。
- **环境错误被掩盖**：用 shim、`0 tests` 或权限绕过制造通过。保留原始失败和未验证范围。
- **用户找不到产物**：只报告文件生成。明确入口、位置、当前运行状态和打开方式。
